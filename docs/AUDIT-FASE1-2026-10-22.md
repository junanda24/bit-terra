## HIGH (7)

### SQL
- **SQL-H1 — DML/DDL tereksekusi dari editor dan merusak DB sesi secara diam-diam.**
  `UPDATE/DELETE/INSERT/DROP` lolos linter (probe B1–B5), runner dibuat sekali
  per quest dan tidak pernah di-reset per RUN → quest tak bisa dimenangkan
  sisa sesi, narasi menyalahkan sebab yang salah; input multi-statement
  perusak bahkan DINYATAKAN LULUS oleh diff checker (A1b). Blueprint menjanjikan
  eksperimen dengan AUTO-ROLLBACK — bukan kerusakan permanen.
- **SQL-H2 — False positive linter memblokir SQL sah di gerbang RUN.**
  Alias output di `ORDER BY` (C3), nama CTE (C10), identifier kurung siku (C6)
  dituduh tidak ditemukan; gerbang RUN menolak eksekusi bila ada 1 error pun
  (CyberDeckScreen:531–538). Jawaban benar yang tidak bisa diserahkan.

### Script
- **SCR-H1 — Kabur penuh dari sandbox: JavaScript arbitrer tereksekusi.**
  `[piko.boot.constructor][0]('return 6*7')()` berjalan tanpa error (E5b);
  `('return this')()` mengembalikan `globalThis` asli (E5c). Akar: pembacaan
  member mengembalikan nilai host hidup (`StepInterpreter.ts:220`, `memberRef`
  :148) dan cabang evalCall 4 (:519) memanggil fungsi apa pun yang terjangkau.
  Janji zero-eval README/blueprint gugur sampai ini diperbaiki.
- **SCR-H2 — Polusi `Object.prototype` dari kode pemain.**
  `sensor.__proto__.x = …` (juga via computed) tertulis tanpa error (E4a/E4b);
  setter `memberRef` (:173/:188) tanpa blocklist. Integritas halaman hilang,
  persisten antar-run.
- **SCR-H3 — Rekursi eksponensial membekukan game; tidak ada anggaran kerja total.**
  `fib(26)` = 17,4 dtk CPU murni / 392.836 StepEvent tanpa penjaga menyala
  (F7); di consumer nyata (±80 ms/event) ≈ 8,7 jam; watchdog tak bisa
  menembak karena event terus mengalir. RunContext hanya melacak loop &
  kedalaman (:130).

### Core
